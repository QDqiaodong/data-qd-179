# 主辅修联合审核（`credit-awards`，独立报告 `schema_version: 1`）

## 要解决的问题

原审核（`credit-audit`，v1/v2）能确定每名学生取得了哪些课程学分，但不记录这些
课分别用于满足哪张证书的要求。教务处需要在**同一份成绩快照**上同时核对主修毕业
与辅修结业，且一门课只能用于一个用途：

- 一门已取得学分的课只能留在主修，或整门划给**一个**辅修要求组；
- 辅修内部也不能用同一门课填两组要求；
- 优先保住主修进度，在此基础上尽可能让辅修达标；
- 外校转学分按哪套方案认定会改变可用证据，因此认定与分配必须联合决策。

本命令不改变任何考试、先修、重修选分或转学分事实，只在既有审核证据之上做证书
用途分配；原 `credit-audit` 等命令的入口、规则与输出完全不变。

## 输入契约

在 v1/v2 原字段之外新增**必填**顶层 `awards` 对象，含 `student_ids` 与 `groups`；
原字段的全部上限、排序与错误行为不变。

### `student_ids`

- 最多 12 个、不重复、全部为已知学生 ID 的字符串数组，**可以为空数组**。
- 只为列出的学生输出主辅修报告；其他学生与未来记录仍按原数据完整校验，只是不
  出现在本报告中。
- 学生按 ID 排序输出；输入数组的重排不改变结果。

### `groups`（1 至 4 个辅修要求组）

每项恰含 `id`、`course_ids`、`minimum_credits`、`source` 四个键，多键或缺键都
拒绝整份输入：

- `id`：非空字符串，组间不重复。
- `course_ids`：非空字符串数组，组内不重复，必须引用现有课程。
- `minimum_credits`：正整数，拒绝布尔值与浮点。下限即使超过候选课程的学分总和
  也是合法配置，报告中如实显示缺口，不视为输入错误。
- `source`：仅取 `any` 或 `exam`。
  - `any`：转学分来源或本校考试来源的课都可划入本组；
  - `exam`：只接受**最终证据**为合法本校及格的课。早先的转学分若解锁了后续
    合法考试，该考试的最终来源仍是 `exam`，可以进 `exam` 组；最终来源为
    `transfer` 的课不能进 `exam` 组。
- 全部组合计最多引用 10 门不同课程；每门课最多出现在两个组中。

### 转学分小批次边界

出现顶层 `transfer`（v2）时，对**本次列出的**每名学生，截至 `as_of` 已生效
（`effective_date <= as_of`）的候选方案最多 6 个，超出即拒绝整份输入。尚未生效
的方案仍按原规则（每生最多 12 个）完整校验，不因截至日而豁免结构检查；未列入
`student_ids` 的学生不受这条新边界约束。

新增字段缺失、类型错误、空 ID、未知引用、重复或超限时拒绝整份输入，退出码 2，
不产生报告；原输入限制全部保留。

## 候选空间：先定证据，再分用途

对同一名学生，先确定一组可用的转学分方案及其实际带来的审核证据，再给这些证据
分配用途，最终从所有这样的“方案 × 分配”组合里选一份最优结果。

- 没有 `transfer` 时只有一份证据，即现有 v1 审核结果（v1 已获学分课程均为考试
  来源）。
- 有 `transfer` 时，沿用原有的全部整包规则枚举可行方案组合（空方案也可选）：
  共享凭据互斥、重复转入课程互斥、额度按目标课程原学分全额计费、仅已生效方案
  可选。**每一组**可行方案都等同于按该方案从头审核：同日不解锁先修、被阻断的
  考试不计学分、重修按“最高分/最早日期/ID”选分、本校合法及格优先于转学分成为
  该课最终来源。不能只拿旧 `credit-audit` 选好的方案做分配。
- 证书用途不影响先修资格，也不改写考试、选分、转学分事实或原审核规则。

## 分配规则

在一份固定证据上，对该生**已取得学分**的课程做分配：

1. 主修必修课（`program.required_courses`）只要取得了学分，就必须留在主修，不
   参与辅修分配。
2. 其他已获学分的课可以整门划给一个辅修组，前提是该组列出了这门课且来源要求
   相符（见上）。未划到辅修的课全部留在主修。
3. 划给辅修的整门课：不能再参与主修类别下限，不能分拆学分，也不能同时参与第二
   个辅修组。
4. 主修按原 `program.required_courses` 与 `program.minimum_credits`，只对留作主
   修的课程判断；辅修各组只累计实际分到本组的学分，全部组达到各自下限才算辅修
   达标。
5. 主修与辅修同时达标，才存在一份支持同时核发的结果；学分不够时仍返回最佳分配
   与真实缺口，不报错。

## 逐级比较序

每名学生在完整候选空间内按以下顺序逐级比较，先分出胜负者胜出。缺口一律定义为
“下限减实得，与零取较大者”。

1. **主修层**：先取主修达标；再取主修缺少的必修数更少；再取主修各类别缺口之和
   更小。
2. **辅修层**：再取辅修达标；再取辅修各组缺口之和更小；再取实际划给辅修的总学
   分更少。整门课超过组下限的部分照计分配成本（例如 5 学分的课填 3 学分下限，
   仍计 5 学分成本，缺口为 0）。
3. **v2 分配前审核平局规则**：仍相同时，沿用原转学分排序比较这几个候选的
   **分配前**审核结果——是否可毕业、已覆盖的必修数、达到各类别下限以内的学分之
   和、原总学分依次取较优，再按认定额度成本更低、方案数更少、排序后的方案 ID
   列表字典序更小。
4. **最终平局规则**：取实际分配的 `(组 ID, 课程 ID)` 排序列表字典序最小者，使用
   Python 字符串顺序；没有分配时是空列表（小于任何非空列表）。v1 证据固定，直接
   使用本规则。

## 报告结构

```json
{
  "schema_version": 1,
  "as_of": "…",
  "students": [
    {
      "student_id": "…",
      "evidence_audit": { /* 原审核学生行结构，内容来自最终所选证据 */ },
      "primary": {
        "course_ids": ["…"],
        "credits": 0,
        "credits_by_category": {"…": 0},
        "missing_required": ["…"],
        "credit_deficits": {"…": 0},
        "eligible": true
      },
      "secondary": {
        "eligible": true,
        "credits": 0,
        "groups": [
          {"id": "…", "course_ids": ["…"], "credits": 0, "deficit": 0}
        ]
      }
    }
  ]
}
```

- 学生按 ID 排序；空 `student_ids` 输出空数组。
- `evidence_audit` 使用原审核学生行结构（v1 无 `source`/`recognition_plan`，
  v2 含 `selected_passes[*].source` 与 `recognition_plan`）。v2 的
  `recognition_plan.objective` 仍是**这套方案自身分配前**的原指标，不表示这套
  方案在旧 `credit-audit` 命令中也会获选。
- `primary.course_ids` 升序；`missing_required` 按 ID 升序；
  `credits_by_category` 包括零学分的课程类别，类别键与缺口键沿用原口径。
- `secondary.groups` 按组 ID 排序，组内 `course_ids` 升序；`deficit` 为该组真实
  缺口。报告里每门分配课程都可用 `course_id` 在 `evidence_audit.selected_passes`
  中查到来源（v1 全为考试，v2 看 `source` 字段）。
- 原始证据学分与证书分配后的数字不混用：证据行的 `credits` 恒等于
  `primary.credits + secondary.credits`。

## 规模与实现边界

- 枚举只按课程与方案的**个数**进行（至多 6 个已生效方案 → 可行方案组合至多
  2⁶=64 份；每份证据上至多 10 门候选课程参与分配枚举），从不按学分或下限的数值
  大小展开数组或迭代；学分与下限没有小整数上界。
- 仅用 Python 标准库；沿用项目统一的有界 JSON 加载、成功时原子新建结果、失败
  退出 2 且保留原输出目标的习惯。

## 验收例摘要

- **反逐组贪心（v1）**：B、A、C、D 均为 3 学分 STEM 本校及格，B 是主修必修，
  STEM 下限 6；实践组可用 C 或 D、项目组只能用 C，各需 3 学分。精确最优把 D 给
  实践、C 给项目，B、A 留在主修。去掉 A 的及格后只剩 B/C/D 三门，主修 6 学分必
  须保住，两组无法同时填满：按末级字典序 C 划给实践，项目组显示 3 学分缺口。
- **v2 联合决策**：A、C 无先修，D 先修 A、E 先修 C，五门均为 3 学分 STEM；学生
  有 B、D、E 同日高分考试，互斥方案 `aa`/`zz` 分别在前一日认定 C、A，额度 3。
  旧 `credit-audit` 选 `aa`（覆盖 E 后总学分更高）；联合审核因辅修只接受 D 的考
  试来源而必须选 `zz`（认定 A 解锁次日 D 考试），D 划给辅修、B 与 A 留在主修。
  把 `zz` 延到与 D 考试同日，则同日不解锁，D 被先修阻断，联合审核回落到 `aa`
  且辅修显示缺口。
