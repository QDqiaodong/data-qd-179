# 匿名答卷对账与毕业结论核验（credit-reconcile）

纸质考试补做电子归档时，考务处的座位表记录学生、课程与考试日，阅卷处的
答卷只有匿名编号、分数与考务处提供的候选链接；部分编号损坏后，一张答卷
可能对应多个座位。本模块在不臆造归属的前提下完成两件事：

1. **对账**：逐批保留所有同样受证据支持的最优匹配，给出每个座位可能对应
   的答卷集合，以及它是否可能在最优匹配中空着；
2. **毕业结论核验**：对每份可能归档从头重走原 v1/v2 学分审核，给出每名
   学生在所有可能归档下的学分区间与毕业确定性，并交付可复算的见证
   （witness）。

## 输入契约

在现有 v1/v2 审核数据（`as_of`、`courses`、`students`、`program`、
`attempts`、可选 `transfer`）之上新增**必填**顶层字段
`reconciliation.waves`；合法的空数组 `[]` 表示没有待对账资料，此时报告
等价于对原确认考试做一次普通审核。

- `waves`：最多 120 个阅卷批次，批次 ID 在批次类别内全局唯一。
- 每个批次为 `{id, seats, sheets}`，同批可含多个课程或考试日；
  - `seats` 最多 6 个，座位为 `{id, student_id, course_id, date}`，座位 ID
    在座位类别内全局唯一，且不得与任何已确认考试 ID 重复；
  - `sheets` 最多 6 张，答卷为 `{id, mark, candidates}`，答卷 ID 在答卷
    类别内全局唯一，`mark` 沿用 0..100 整数口径（拒绝布尔值）；
  - 每个候选为 `{seat_id, verified}`，`verified` 必须是布尔值，`true`
    表示另有签收记录支持这条链接。
- 禁止跨批引用候选座位；同一张答卷不得重复列同一座位；学生、课程引用
  必须存在。缺少候选的答卷与没有候选答卷的座位都是合法输入。
- 座位与已确认考试合在一起不超过 20000 条，且合在一起时
  `(student_id, course_id, date)` 不得重复。
- 每个座位最多被 3 张答卷列为候选；每名学生在全输入中最多有 3 个待对账
  座位。
- 新字段的类型错误或不合法引用一律拒绝整份输入，**即使相关答卷永远不会
  匹配、或座位日期晚于 `as_of`**：未来数据只在成绩审核阶段被截至日排除，
  结构校验从不跳过。

## 对账规则（每批独立）

- 匹配只能使用给定的候选链接；一张答卷与一个座位各至多使用一次。
- 目标按顺序比较：先取**匹配对数最多**的匹配，再在其中取 **verified
  链接数最多**的匹配；所有并列最优匹配全部保留。
- 分数、毕业与否、输入数组顺序都不参与对账。
- 同一批内单独可行的两条链接不一定能共同发生（例如两张答卷都只链接同一
  个座位，二者互斥）。
- 全批次都参与对账，包含未来日期；`as_of` 只在随后的学分审核中起作用。

每个批次各选一个最优匹配才构成一份可能归档。匹配上的座位产生一条考试：
考试 ID、学生、课程、日期取自座位，分数取自匹配答卷；未匹配座位不产生
考试；既有 `attempts` 全部保留。

## 审核语义与计算界限

每份可能归档的审核语义等同于把其中已确认考试与匹配产生的考试按原规则
完整审核。实际归属会改变先修链、重修选分与毕业要求；v2 输入下也可能
改变最优转学分认定（`recognition_plan`），因此实现**从不冻结原先认定再
贴匿名成绩**，而是对每份归档重新执行 v1 的 `student_result` 或 v2 的
`student_transfer_result`（含整包方案枚举与全局最优选择）。

### 不构造整届笛卡尔积

分批归档的可能性随批数指数增长，但一名学生的结论只依赖与该生座位有关的
批次。实现按学生做**本地投影**：对每个相关批次，只收集该生自己的座位在
任一最优匹配中能拿到的答卷向量（去重），再对这些批次的投影做笛卡尔积；
不含该生座位的批次根本不进入该生的枚举。

可重复的审核次数因此是：

- 学生没有待对账座位：恰好 **1** 次（只审原确认考试）；
- 否则为 **∏（各相关批次的本地投影数）**。

每个座位最多被 3 张答卷列为候选，加上“在某最优匹配中空着”这一可能，
单个批次对单个学生的投影数至多为 4；每名学生至多有 3 个待对账座位，故
单生审核次数恒有上界 **4³ = 64**，与总批数无关。增加一个不含该生座位的
独立批次不会让该生多审核一次。测试 `tests/test_reconciliation.py` 的
`AuditBoundTests` 用 61 个批次（60 个彼此独立、各含并列匹配的批次）断言
实际计数：每名学生始终只审核 2 次，总审核次数 244，而整届笛卡尔积会是
2⁶¹ 份归档——界限由计数证明，不依赖耗时推断。引擎
`registrar.reconciliation._Reconciler` 暴露 `audit_count` 与
`audits_by_student` 供复核。

注意不能用单条考试可能性的并集或交集做一次审核，也不能把某一组并列匹配
当成官方结果：见证必须对应一份完整、可复算的归档。

## 报告

报告为 `{schema_version: 1, as_of, waves, students}`：

- `waves` 按批次 ID 排序，每项含 `id`、`matched_count`、
  `verified_count` 与按座位 ID 排序的 `seats`。每个座位列
  `{seat_id, possible_sheet_ids, may_be_unmatched}`：
  - `possible_sheet_ids` 是该批任一最优匹配能分给该座位的答卷 ID 去重
    升序集合；
  - `may_be_unmatched` 表示是否存在让该座位空着的最优匹配。
- `students` 按学生 ID 排序，每项含：
  - `student_id`；
  - `credit_range`：所有可能归档下最小学分与最大学分组成的二元数组；
  - `graduation_status`：所有归档均合格为 `eligible`，均不合格为
    `ineligible`，两种都可能为 `needs_review`；
  - `witnesses`：`eligible`、`ineligible` 两个键分别给出一个实际合格或
    不合格的见证，不可能出现的结果为 `null`。

### 见证（witness）

每个见证含：

- `audit`：该归档中此学生的完整原审核学生行（v1/v2 全部原有字段，v2
  含重新选择后的 `recognition_plan`）；
- `assignments`：含该生任一待对账座位的**全部批次**的完整匹配，按
  `(wave_id, seat_id)` 排列的 `{wave_id, seat_id, sheet_id}` 数组，未
  匹配的座位 `sheet_id` 为 `null`，且包含这些批次中其他学生的座位；无关
  批次不写入。学生没有待对账座位时为空数组。

每一类结果取按上述顺序比较 `sheet_id` 向量时字典序最小的见证，`null`
排在所有字符串之后；全部比较使用 Python 字符串顺序。因此输入数组如何
重排都不会改变报告。

## 命令行

安装后提供：

```sh
credit-reconcile --source JSON --output JSON
```

沿用原项目有界 JSON 加载（防重复键、拒绝非有限常数、8 MB 上限）与原子
新建报告方式：成功退出 0 并向 stdout 输出一行汇总
（`waves/students/needs_review/eligible/ineligible` 计数）；输入或业务
规则无效、输出路径已存在时退出 2 且保留原输出目标，不产生部分写入。

## 端到端演示

```sh
credit-reconcile --source fixtures/input_reconcile.json \
                 --output run/report-reconcile.json
```

预期（见 `fixtures/input_reconcile.json`）：

- `wave-amber`：甲（jia）、乙（yi）两个 A 课座位与一张高分、一张低分
  答卷两两可链接且均无签收，两个最优匹配并列（各成 2 对、0 条 verified），
  两座位的 `possible_sheet_ids` 均为两份答卷且都不可能空着；
- 甲另有后来的 B 考试（B 要求先完成 A），故甲为 `needs_review`，学分
  区间 `[0, 6]`：高分归属甲时 B 正常通过、可以毕业；低分归属甲时 A 不
  及格、B 被先修阻断。两份见证中 B 的 `status` 分别为 `passed` 与
  `blocked_prerequisite`；
- `wave-blue`：丙（bing）在不同日有两个 D 座位，一份及格答卷可去任一
  座位且必须匹配；具体归属不确定，但丙确定取得 D 的 2 学分，因培养方案
  要求 A、B，结论确定为 `ineligible`，两个座位都 `may_be_unmatched: true`；
- `wave-coral`：甲的未来 D 座位带签收、唯一匹配；对账照常成 1 对，但
  该考试晚于 `as_of`，见证审核的 `ignored_future_attempts` 为 1，不计入
  当前学分。
